> **所属项目**：自律工作台  
> **文档版本**：V1.0  
> **更新日期**：2026-07-29  
> **优先级**：P0（核心功能）

## 一、功能定义

### 1.1 是什么

每天凌晨自动扫描**昨日及之前到期但未完成的任务**，把它们归档到"每日作业"列表中。用户打开App时一眼看到"昨天还有哪些没做"，可以选择**补做 / 改期 / 放弃**，形成完整的执行闭环。

### 1.2 解决什么问题

| 痛点 | 本功能如何应对 |
|------|----------------|
| 昨日任务没做完，今天打开App就"消失了"（被新一天淹没） | 归档保留，今日置顶提醒 |
| 循环任务断了就断了，没有连续记录 | 补做操作让链条可修复 |
| 不知道自己一周哪天最懈怠 | 本周回顾统计给出完成率曲线 |
| 任务列表越积越多变成"垃圾场" | 强制归档+处置，保持主列表干净 |

### 1.3 核心规则

| 规则 | 说明 |
|------|------|
| 归档时间 | 每天 00:00（App端WorkManager） + 00:05（服务端Cron兜底） |
| 归档对象 | `status=0`（未完成）且 `due_date < 今日零点` 的任务 |
| 排除对象 | `task_type=2`（长期目标，不计入每日作业） |
| 处置方式 | 补做 / 放弃 / 改期（三选一） |
| 数据保留 | 归档记录**永不物理删除**，保证历史完整 |
| 原任务删除 | 归档记录保留快照，`original_task_deleted=true` |

## 二、数据模型

### 2.1 数据库表：`daily_pending_log`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | VARCHAR(36) PK | UUID |
| `device_id` | VARCHAR(36) | 设备ID（用户隔离） |
| `log_date` | DATE | 归档日期（哪一天的未完成，如 `2026-07-28`） |

| `task_type` | TINYINT | 原任务类型(0一次性/1循环) |

### 2.4 DAO

```kotlin
@Dao
interface DailyPendingLogDao {

    // 获取某天归档列表
    @Query("SELECT * FROM daily_pending_log WHERE device_id = :deviceId AND log_date = :date AND is_deleted = 0")
    fun getByDate(deviceId: String, date: String): Flow<List<DailyPendingLogEntity>>

    // 获取今日待处理（disposition=0）
    @Query("SELECT * FROM daily_pending_log WHERE device_id = :deviceId AND disposition = 0 AND is_deleted = 0 ORDER BY task_due_date ASC")
    fun getTodayPending(deviceId: String): Flow<List<DailyPendingLogEntity>>

    // 获取某天摘要统计
    @Query("""
        SELECT 
            COUNT(*) as total,
            SUM(CASE WHEN disposition = 1 THEN 1 ELSE 0 END) as completed,
            SUM(CASE WHEN disposition = 2 THEN 1 ELSE 0 END) as abandoned,
            SUM(CASE WHEN disposition = 3 THEN 1 ELSE 0 END) as rescheduled,
            SUM(CASE WHEN disposition = 0 THEN 1 ELSE 0 END) as pending
        FROM daily_pending_log 
        WHERE device_id = :deviceId AND log_date = :date AND is_deleted = 0
    """)
    fun getSummary(deviceId: String, date: String): Flow<PendingSummary>

    // 本周每日完成率
    @Query("""
        SELECT log_date as date, 
               COUNT(*) as total,
               SUM(CASE WHEN disposition = 1 THEN 1 ELSE 0 END) as completed
        FROM daily_pending_log 
        WHERE device_id = :deviceId 
          AND log_date >= :weekStart 
          AND log_date <= :weekEnd
          AND is_deleted = 0
        GROUP BY log_date
        ORDER BY log_date
    """)
    fun getWeeklyStats(deviceId: String, weekStart: String, weekEnd: String): Flow<List<DailyStat>>

    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun insert(log: DailyPendingLogEntity)

    @Update
    suspend fun update(log: DailyPendingLogEntity)

    @Query("UPDATE daily_pending_log SET disposition = :disp, disposed_at = :time, last_modified = :time, needs_sync = 1 WHERE id = :id")
    suspend fun updateDisposition(id: String, disp: Int, time: Long = System.currentTimeMillis())

    @Query("SELECT * FROM daily_pending_log WHERE needs_sync = 1")
    suspend fun getPendingSync(): List<DailyPendingLogEntity>

    @Query("UPDATE daily_pending_log SET needs_sync = 0 WHERE id IN (:ids)")
    suspend fun markSynced(ids: List<String>)
}
```

## 三、业务流程

### 3.1 每日归档流程

```
触发方式（双保险）：
  ① App端 WorkManager → 每天 00:00 执行
  ② 服务端 Cron      → 每天 00:05 执行PHP脚本

流程：
  1. 查询所有 status=0 AND is_deleted=0 AND due_date < 今日零点 的任务
  2. 排除 task_type=2（长期目标）
  3. 对每条记录：
     INSERT INTO daily_pending_log (
       device_id, log_date=昨日, task_id, task_title快照, ...
     )
  4. 返回归档数量
  5. 前端下次打开App时拉取今日归档列表
```

### 3.2 补做 / 放弃 / 改期

```
┌─────────────────────────────────────┐
│  用户看到"昨日未完成：背单词"       │
├─────────────────────────────────────┤
│  [补做]  → 标记归档=已补做       │
│           → 同时把原任务标完成      │
│           → 循环任务自动计算下次    │
├─────────────────────────────────────┤
│  [放弃]  → 只标记归档=已放弃      │
│           → 原任务不动             │
│           → 永不骚扰用户            │
├─────────────────────────────────────┤
│  [改期]  → 弹出日期选择器         │
│           → 修改原任务due_date     │
│           → 标记归档=已改期        │
│           → 循环任务延后一天        │
└─────────────────────────────────────┘
```

### 3.3 状态机

```
              ┌──────────┐
              │  待处理   │  disposition=0
              └────┬─────┘
         ┌─────────┼─────────┐
         ▼         ▼         ▼
    ┌────────┐ ┌────────┐ ┌────────┐
    │ 已补做 │ │ 已放弃 │ │ 已改期 │
    │   +1   │ │  不变  │ │ 延后  │
    └────────┘ └────────┘ └────────┘
    
    不可逆：一旦处置，不可回退（保证数据一致性）
```

## 四、App端实现

### 4.1 归档Worker

```kotlin
class DailyArchiveWorker(
    context: Context,
    params: WorkerParameters
) : CoroutineWorker(context, params) {

    override suspend fun doWork(): Result {
        return try {
            val deviceId = getDeviceId()
            val today = LocalDate.now()
            val yesterday = today.minusDays(1)
            val todayMidnight = today.atStartOfDay(ZoneId.systemDefault()).toEpochSecond() * 1000

            // 1. 查找昨日及之前到期、未完成的任务
            val overdueTasks = taskRepository.getOverdueTasks(before = todayMidnight)

            // 2. 逐条写入归档表（排除长期目标）
            overdueTasks.forEach { task ->
                if (task.taskType != 2) {
                    dailyLogRepository.insert(
                        DailyPendingLogEntity(
                            deviceId = deviceId,
                            logDate = yesterday.toString(),  // "2026-07-28"
                            taskId = task.id,
                            taskTitle = task.title,
                            taskCategoryId = task.categoryId,
                            taskCategoryName = task.categoryName,
                            taskDueDate = task.dueDate,
                            taskType = task.taskType
                            // disposition 默认为 0（待处理）
                        )
                    )
                }
            }

            // 3. 触发同步
            syncManager.syncNow()

            Result.success()
        } catch (e: Exception) {
            Result.retry()
        }
    }

    companion object {
        fun schedule(context: Context) {
            val delay = calculateDelayToMidnight()

            val request = PeriodicWorkRequestBuilder<DailyArchiveWorker>(
                repeatInterval = 1, TimeUnit.DAYS
            )
                .setInitialDelay(delay, TimeUnit.MILLISECONDS)
                .setBackoffCriteria(BackoffPolicy.EXPONENTIAL, 1, TimeUnit.MINUTES)
                .build()

            WorkManager.getInstance(context)
                .enqueueUniquePeriodicWork(
                    "daily_archive",
                    ExistingPeriodicWorkPolicy.REPLACE,
                    request
                )
        }

        private fun calculateDelayToMidnight(): Long {
            val now = Calendar.getInstance()
            val midnight = Calendar.getInstance().apply {
                add(Calendar.DAY_OF_MONTH, 1)
                set(Calendar.HOUR_OF_DAY, 0)
                set(Calendar.MINUTE, 0)
                set(Calendar.SECOND, 5)  // 多5秒防止边界问题
                set(Calendar.MILLISECOND, 0)
            }
            return midnight.timeInMillis - now.timeInMillis
        }
    }
}
```

### 4.2 处置操作

```kotlin
class DailyPendingRepositoryImpl(
    private val dao: DailyPendingLogDao,
    private val taskRepository: TaskRepository
) : DailyPendingRepository {

    override suspend fun completePending(logId: String) {
        val log = dao.getById(logId) ?: return
        val now = System.currentTimeMillis()

        // 1. 标记归档=已补做
        dao.updateDisposition(logId, disp = 1, time = now)

        // 2. 原任务仍存在 → 标记完成
        if (!log.originalTaskDeleted) {
            taskRepository.completeTask(log.taskId)
        }
    }

    override suspend fun abandonPending(logId: String) {
        val now = System.currentTimeMillis()
        // 只标记归档=已放弃，不动原任务
        dao.updateDisposition(logId, disp = 2, time = now)
    }

    override suspend fun reschedulePending(logId: String, newDueDate: Long) {
        val log = dao.getById(logId) ?: return
        val now = System.currentTimeMillis()

        // 1. 修改原任务截止时间
        if (!log.originalTaskDeleted) {
            taskRepository.updateDueDate(log.taskId, newDueDate)
        }

        // 2. 标记归档=已改期
        dao.updateDisposition(logId, disp = 3, time = now)
    }
}
```

### 6.2 实现代码

```kotlin
class DailyPendingReminder @Inject constructor(
    private val context: Context,
    private val scheduler: NotificationScheduler,
    private val repository: DailyPendingRepository
) {
    private val alarmManager = context.getSystemService(AlarmManager::class.java)

    fun scheduleMorningReminder() {
        val triggerAt = getNext8AM()
        val intent = Intent(context, NotificationReceiver::class.java).apply {
            putExtra(EXTRA_TYPE, TYPE_DAILY_PENDING)
            putExtra(EXTRA_TITLE, "昨日有未完成项")
            putExtra(EXTRA_BODY, "今天加油补上！")
        }
        val pi = PendingIntent.getBroadcast(
            context, "daily_pending_morning".hashCode(), intent,
            PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE
        )
        alarmManager.setExactAndAllowWhileIdle(
            AlarmManager.RTC_WAKEUP, triggerAt, pi
        )
    }

    fun scheduleWeeklyReview() {
        val triggerAt = getNextSunday8PM()
        val intent = Intent(context, NotificationReceiver::class.java).apply {
            putExtra(EXTRA_TYPE, TYPE_WEEKLY_REVIEW)
        }
        val pi = PendingIntent.getBroadcast(
            context, "weekly_review".hashCode(), intent,
            PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE
        )
        alarmManager.setExactAndAllowWhileIdle(
            AlarmManager.RTC_WAKEUP, triggerAt, pi
        )
    }

    private fun getNext8AM(): Long {
        val cal = Calendar.getInstance().apply {
            set(Calendar.HOUR_OF_DAY, 8)
            set(Calendar.MINUTE, 0)
            set(Calendar.SECOND, 0)
            if (before(Calendar.getInstance())) add(Calendar.DAY_OF_MONTH, 1)
        }
        return cal.timeInMillis
    }

    private fun getNextSunday8PM(): Long {
        val cal = Calendar.getInstance().apply {
            set(Calendar.DAY_OF_WEEK, Calendar.SUNDAY)
            set(Calendar.HOUR_OF_DAY, 20)
            set(Calendar.MINUTE, 0)
            if (before(Calendar.getInstance())) add(Calendar.WEEK_OF_YEAR, 1)
        }
        return cal.timeInMillis
    }
}
```

```php
<?php
// src/Controllers/DailyPendingController.php

class DailyPendingController {
    private $model;
    private $deviceId;
    
    public function __construct() {
        $this->model = new DailyPendingLogModel();
        $this->deviceId = Auth::getDeviceId();
    }
    
    // GET /daily-pending?date=2026-07-28
    public function list() {
        $date = $_GET['date'] ?? date('Y-m-d', strtotime('yesterday'));
        $items = $this->model->getByDate($this->deviceId, $date);
        $summary = $this->model->getSummary($this->deviceId, $date);
        
        Response::success([
            'date' => $date,
            'items' => $items,
            'summary' => $summary
        ]);
    }
    
    // GET /daily-pending/today
    public function today() {
        $items = $this->model->getPending($this->deviceId);
        Response::success(['items' => $items]);
    }
    
    // POST /daily-pending/:id/complete
    public function complete($id) {
        $log = $this->model->getById($this->deviceId, $id);
        if (!$log) Response::error('Record not found', 404, 404);
        
        // 标记归档=已补做
        $this->model->updateDisposition($this->deviceId, $id, 1);
        
        // 原任务仍存在 → 标记完成
        if (!$log['original_task_deleted']) {
            $taskModel = new TaskModel();
            $taskModel->complete($this->deviceId, $log['task_id']);
        }
        
        Response::success();
    }
    
    // POST /daily-pending/:id/abandon
    public function abandon($id) {
        $this->model->updateDisposition($this->deviceId, $id, 2);
        Response::success();
    }
    
    // POST /daily-pending/:id/reschedule
    public function reschedule($id) {
        $input = json_decode(file_get_contents('php://input'), true);
        $newDueDate = $input['newDueDate'] ?? 0;
        
        $log = $this->model->getById($this->deviceId, $id);
        if (!$log) Response::error('Record not found', 404, 404);
        
        // 修改原任务截止时间
        if (!$log['original_task_deleted'] && $newDueDate > 0) {
            $taskModel = new TaskModel();
            $taskModel->updateDueDate($this->deviceId, $log['task_id'], $newDueDate);
        }
        
        $this->model->updateDisposition($this->deviceId, $id, 3);
        Response::success();
    }
    
    // GET /daily-pending/weekly?weekStart=2026-07-24
    public function weekly() {
        $weekStart = $_GET['weekStart'] ?? date('Y-m-d', strtotime('monday this week'));
        $days = [];
        
        for ($i = 0; $i < 7; $i++) {
            $date = date('Y-m-d', strtotime($weekStart . " +{$i} days"));
            $summary = $this->model->getSummary($this->deviceId, $date);
            $rate = $summary['total'] > 0 
                ? round($summary['completed'] / $summary['total'], 2) 
                : 1.0;
            $days[] = [
                'date' => $date,
                'total' => (int)$summary['total'],
                'completed' => (int)$summary['completed'],
                'rate' => $rate
            ];
        }
        
        $avg = count($days) > 0 
            ? array_sum(array_column($days, 'rate')) / count($days) 
            : 0;
        
        Response::success([
            'days' => $days,
            'weeklyAverage' => round($avg, 2)
        ]);
    }
}
```

### 7.3 Model

```php
<?php
// src/Models/DailyPendingLogModel.php

class DailyPendingLogModel {
    private $db;
    
    public function __construct() {
        $this->db = Database::get();
    }
    
    public function insert($data) {
        $sql = "INSERT INTO daily_pending_log 
                (id, device_id, log_date, task_id, task_title, 
                 task_category_id, task_category_name, task_due_date, 
                 task_type, disposition, last_modified)
                VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, 0, ?)
                ON DUPLICATE KEY UPDATE last_modified = VALUES(last_modified)";
        
        $stmt = $this->db->prepare($sql);
        $stmt->execute([
            $data['id'] ?? $this->generateUuid(),
            $data['device_id'],
            $data['log_date'],
            $data['task_id'],
            $data['task_title'],
            $data['task_category_id'] ?? null,
            $data['task_category_name'] ?? null,
            $data['task_due_date'] ?? null,
            $data['task_type'] ?? 0,
            $data['last_modified'] ?? round(microtime(true) * 1000)
        ]);
    }
    
    public function getByDate($deviceId, $date) {
        $stmt = $this->db->prepare(
            "SELECT * FROM daily_pending_log 
             WHERE device_id = ? AND log_date = ? AND is_deleted = 0
             ORDER BY task_due_date ASC"
        );
        $stmt->execute([$deviceId, $date]);
        return $stmt->fetchAll();
    }
    
    public function getPending($deviceId) {
        $stmt = $this->db->prepare(
            "SELECT * FROM daily_pending_log 
             WHERE device_id = ? AND disposition = 0 AND is_deleted = 0
             ORDER BY log_date DESC, task_due_date ASC"
        );
        $stmt->execute([$deviceId]);
        return $stmt->fetchAll();
    }
    
    public function getById($deviceId, $id) {
        $stmt = $this->db->prepare(
            "SELECT * FROM daily_pending_log 
             WHERE device_id = ? AND id = ?"
        );
        $stmt->execute([$deviceId, $id]);
        return $stmt->fetch();
    }
    
    public function updateDisposition($deviceId, $id, $disposition) {
        $stmt = $this->db->prepare(
            "UPDATE daily_pending_log 
             SET disposition = ?, disposed_at = ?, last_modified = ?
             WHERE device_id = ? AND id = ?"
        );
        $time = round(microtime(true) * 1000);
        $stmt->execute([$disposition, $time, $time, $deviceId, $id]);
    }
    
    public function getSummary($deviceId, $date) {
        $stmt = $this->db->prepare(
            "SELECT 
                COUNT(*) as total,
                COALESCE(SUM(CASE WHEN disposition = 1 THEN 1 ELSE 0 END), 0) as completed,
                COALESCE(SUM(CASE WHEN disposition = 2 THEN 1 ELSE 0 END), 0) as abandoned,
                COALESCE(SUM(CASE WHEN disposition = 3 THEN 1 ELSE 0 END), 0) as rescheduled,
                COALESCE(SUM(CASE WHEN disposition = 0 THEN 1 ELSE 0 END), 0) as pending
             FROM daily_pending_log
             WHERE device_id = ? AND log_date = ? AND is_deleted = 0"
        );
        $stmt->execute([$deviceId, $date]);
        return $stmt->fetch();
    }
    
    private function generateUuid() {
        return sprintf('%04x%04x-%04x-%04x-%04x-%04x%04x%04x',
            mt_rand(0, 0xffff), mt_rand(0, 0xffff),
            mt_rand(0, 0xffff),
            mt_rand(0, 0x0fff) | 0x4000,
            mt_rand(0, 0x3fff) | 0x8000,
            mt_rand(0, 0xffff), mt_rand(0, 0xffff), mt_rand(0, 0xffff)
        );
    }
}
```

## 八、同步处理

### 8.1 同步规则

归档记录遵循统一的同步机制：

| 操作 | needsSync | 同步方向 |
|------|-----------|----------|
| App端归档写入 | true | 上传到云端 |
| 补做/放弃/改期 | true | 上传到云端 |
| 云端拉取 | false | 下载到本地 |

### 8.2 特殊处理

| 场景 | 处理方式 |
|------|----------|
| 原任务被删除 | 归档记录保留快照，`original_task_deleted=true` |
| 归档记录冲突 | LWW（Last-Write-Wins），比较last_modified |
| 多设备归档重复 | 主键是UUID，不会重复；Cron和WorkManager可能双写同一任务 |
| 防止双写 | 写入前先查 `WHERE task_id=? AND log_date=?`，已存在则跳过 |

### 8.3 防止双写逻辑

## 十二、注意事项

| 问题 | 解决方案 |
|------|----------|
| WorkManager在00:00不一定准时执行 | Cron兜底，5分钟后二次扫描 |
| 用户跨时区怎么办 | 归档时间以服务器时区为准（统一UTC+8） |
| 循环任务归档后还要继续 | 补做只标完成，循环任务下次到期自动生成 |
| 大量历史数据拖慢查询 | 按月分区或归档到历史表 |
| 用户删了原任务但归档还在 | 保留快照，显示"原任务已删除"标记 |
|  dispositon改错了无法回退 | 个人项目可接受，后续可加"撤销"按钮 |
